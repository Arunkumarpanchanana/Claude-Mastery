Unlock persistent context, organized workflows, and reusable knowledge by mastering Claude Projects and the Artifacts feature.

Claude Projects: Solving the Memory Problem

We covered in Session 7 that Claude has no persistent memory by default. Every conversation starts fresh. Claude Projects is Anthropic's solution for ongoing work that spans multiple sessions.

A Project is a dedicated workspace within Claude.ai that:

  • Maintains a set of knowledge documents that are loaded into every conversation's context
  • Preserves a persistent instruction set (custom system prompt) for all conversations in the project
  • Keeps a conversation history within the project so you can return to previous sessions
  • Allows you to upload and reference files that Claude can access across sessions
The practical effect: With Projects, Claude effectively "knows" your role, preferences, ongoing goals, and key background without you re-stating it every session. It's the difference between working with a new contractor each day and working with a dedicated team member who knows your context.

Setting Up a Useful Project

A well-configured project has three key components:

1

Project Instructions (Persistent System Prompt)

This is the most powerful component. Write a detailed instruction set that tells Claude who you are, what the project is for, what style you prefer, and any standing rules or constraints. This appears at the top of every conversation's context.

Good instruction includes: your role and background, preferred response style, the project's purpose and goals, key terminology or conventions, what Claude should and shouldn't assume.

2

Knowledge Documents

Upload documents that Claude should have access to — style guides, company information, reference materials, past work examples. Claude will have this context in every project conversation without you pasting it each time.

Great knowledge docs: brand voice guidelines, technical reference docs, project briefs, persona documents, previous decisions you want Claude to know about.

3

Conversation Organization

Use separate conversations within the project for different sub-tasks or phases. Don't try to do everything in one mega-conversation — each conversation starts fresh with your persistent context, which keeps them focused.

Artifacts: Creating Reusable Outputs

When Claude generates a substantial self-contained piece of work — a document, a code file, a spreadsheet, an SVG image — it may render it as an Artifact: a side panel that displays the output separately from the conversation.

Artifacts have several advantages:

  • They're easier to read — rendered as the document itself, not as text in a chat bubble
  • They're editable in-place — you can ask Claude to modify specific parts without regenerating everything
  • They can be shared — some types of artifacts can be published or exported
  • Code artifacts run — for supported languages, you can execute code directly in the artifact panel

Code Artifacts

HTML, CSS, JavaScript, React components render and run in the artifact panel. You can see the output live and ask Claude to modify specific elements.

Document Artifacts

Markdown documents, reports, letters render as formatted text. You can iterate on specific sections without regenerating the whole document.

Data Artifacts

Tables and structured data render as proper tables. For CSV-style data, Claude can produce cleanly formatted tabular output you can copy directly into spreadsheet tools.

Organizing Knowledge with Claude

Beyond Projects, you can use Claude as a knowledge organization tool — helping you structure, tag, and synthesize information from various sources into reusable formats.

Useful knowledge organization workflows:

  • Meeting notes → Action items: Paste raw notes, ask Claude to extract decisions, owners, and deadlines
  • Research synthesis: Paste multiple sources, ask Claude to find common themes and contradictions
  • Decision logging: After important decisions, have Claude document the decision, rationale, and alternatives considered
  • Knowledge base creation: Ask Claude to convert your informal notes into structured FAQ or wiki-style articles
Power workflow: the project knowledge loop. As you work in a project, periodically ask Claude to summarize the key decisions, learnings, and context from that project. Add this summary as a knowledge document. Over time, the project's knowledge base grows and Claude gets better at supporting your specific work.

Lab: Set Up Your First Claude Project

Create a real working project in Claude.ai with proper instructions and knowledge documents. This project will serve you for the rest of the course and beyond.

1

Choose a real project

Think of an ongoing project or area of work where you'd benefit from Claude having persistent context. Examples:

  • A work project (product launch, research, content creation)
  • A learning goal (studying for a certification, learning a new skill)
  • A creative project (writing a book, building an app)
  • A personal goal (job search, business idea, health journey)

Open Claude.ai, go to the sidebar, and create a new Project.

2

Write your project instructions

Ask Claude (in a regular conversation) to help you write project instructions:

Help me write project instructions for a Claude Project. The project is: [your project]. I am: [your role/background]. My preferred response style: [direct/detailed/etc]. Key context Claude should always have: [key facts]. What Claude should and shouldn't do: [any standing rules].

Format it as a ready-to-paste instruction block.

Review, edit, and paste this into your Project's instruction field.

3

Create and upload a knowledge document

Create one knowledge document for your project. This could be:

  • A reference document (style guide, key definitions, relevant facts)
  • A project brief (goals, timeline, constraints, stakeholders)
  • Previous work examples Claude should match

Ask Claude to help you write it: "Help me create a [type] knowledge document for a project about [topic]. It should include [key sections]."

Upload it to your project.

4

Test your project context

Start a new conversation within the project. Without adding any context, ask Claude something that would only make sense if it had your project instructions and knowledge document.

For example, if your project is about a specific work domain: ask Claude a domain-specific question and see if it responds with the context from your setup.

Does it "know" who you are and what you're working on?

5

Create an Artifact

In your project conversation, ask Claude to produce a substantial output — a document, a plan, a template — that would benefit from the Artifact rendering. Try:

Create a project status dashboard template as a formatted markdown document that I can reuse weekly. Include sections for: key metrics, decisions made, blockers, next week priorities.

Claude should render this as a Document Artifact. Explore how you can iterate on it — "make the metrics section more detailed" — without regenerating the whole document.
