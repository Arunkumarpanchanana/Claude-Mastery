Working Memory & Context Windows

Master how Claude's context window works so you can manage long conversations, pass in the right information, and never lose important context.

25 min Beginner Context Management Lab 5 Quiz Questions

What Is the Context Window?

Claude doesn't have memory in the way humans do. Instead, it has a context window — a fixed-size buffer of tokens that it can "see" at once. Everything in the context window is equally available to Claude when generating each response: your original prompt, every message you've sent, every response Claude has given.

Think of the context window as Claude's working desk. Anything on the desk it can use. Anything not on the desk doesn't exist for it. When you start a new conversation, you clear the desk. The current conversation fills it up progressively.

Claude's context window size: Claude 3 models have context windows up to 200,000 tokens — roughly 150,000 words or about 500 pages. This is very large compared to earlier models, but it's still finite. Long enough to hold a full novel, but not every document you've ever written.

What goes into the context window:

  • The system prompt (if any) — instructions from the operator/platform
  • Every message in the current conversation (both yours and Claude's)
  • Any documents or files you've attached to the conversation
  • Tool outputs (search results, code execution results, etc.)

Why Claude "Forgets" Across Conversations

Starting a new chat with Claude is like talking to someone who has amnesia about all your previous sessions. Claude doesn't remember that you told it last week that you prefer short answers, or that you work as a nurse, or that you're working on a specific project.

This is not a bug — it's a design decision with real tradeoffs:

Why no persistent memory is good

  • Privacy: your conversations aren't accumulated into a dossier
  • Clean slate: each task starts without assumptions
  • No cascading errors: old mistakes don't compound into new ones
  • Security: compromising one conversation doesn't expose all others

The downside

  • You must re-establish context each conversation
  • Personal preferences must be restated
  • Ongoing projects require context-sharing each session
  • Building on previous work requires explicit bridging

Claude's Projects feature (in Claude.ai) partially addresses this by letting you attach persistent context documents and instructions that load at the start of every conversation in that project. We'll cover this in Session 14.

Managing Long Conversations Effectively

As conversations grow long, two things can happen: the context window fills up (forcing older content to be dropped or summarized), and Claude's attention becomes more diffuse (earlier details get "diluted" by later content).

1

Start fresh for new topics

Don't try to do everything in one mega-conversation. A new task that's unrelated to your current conversation is better started fresh. Context from irrelevant past exchanges can confuse or anchor Claude unhelpfully.

2

Summarize periodically

For very long working sessions, ask Claude to summarize the key decisions and context from the conversation so far. Then start a new conversation and paste that summary as your first message.

3

Front-load important context

Put the most important information near the beginning of your conversation (and near the beginning of each message). Claude attends somewhat more reliably to content at the start and end of its context.

4

Use explicit anchoring

If a key constraint or decision was made early in a long conversation, restate it explicitly when it becomes relevant again: "As we established earlier, we're targeting non-technical users..."

Pro tip: Context priming. Starting a conversation with a brief "context block" dramatically improves Claude's performance: "Context: I'm a product manager at a B2B SaaS company. I prefer direct, bulleted answers. I'm working on our Q3 roadmap." This front-loads crucial context so it's available for every response in the session.

Lab: Context Window in Practice

Practice managing context, priming conversations, and handling the memory limitations of Claude.

1

Write your personal context block

Write a 3-5 sentence context block about yourself for use with Claude. Include:

  • Your professional role or area of interest
  • Your preferred response style (concise/detailed, bullets/prose)
  • Any relevant background Claude should know
  • The type of tasks you use Claude for most

Test it by starting a new conversation with this context block and asking Claude something relevant to your work. Compare to asking without the context block.

2

Test cross-conversation memory

In one conversation, tell Claude:

My name is [your name] and I work as a [your job]. Remember this for our conversation.

Then start a brand new conversation and ask: "What's my name and what do I do?" Claude will have no memory of the previous conversation. This makes the amnesia tangible.

3

Practice conversation summarization

Have a 5-10 turn conversation with Claude about any complex topic — planning a project, exploring a technical concept, working through a decision. Then ask:

Please summarize the key points, decisions, and context from our conversation so far in a way that I could paste into a new conversation to continue where we left off.

Then start a new conversation, paste the summary, and continue the work. How well does the bridging work?

4

Paste a large document and query it

Find any long document (a long article, a report, or paste several pages of text) and give it to Claude with a specific task:

Here is [document]. Please [specific question about it].

Notice how Claude can reason about the entire document at once — this is the large context window in action. With 200K tokens, you can pass in entire codebases, books, or research papers and have a conversation about them.

5

Explore Projects (if you have Claude.ai access)

If you have access to Claude.ai, create a new Project and add a project instruction like:

I am a [role]. Always respond in [style]. Key context: [your context]. This project is about: [project topic].

Then start multiple conversations within that project and notice how the context persists. This is the solution to cross-conversation memory for ongoing work.
