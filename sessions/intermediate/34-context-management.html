Context Management & Code Review

Keep Claude Code effective across long sessions with CLAUDE.md, smart context hygiene, and targeted code review prompts.

35 min Intermediate Code Lab 5 Quiz Questions

The CLAUDE.md File

CLAUDE.md is a special file in your project root that Claude Code reads automatically at the start of every session. It's the single best way to give Claude persistent project-specific context without using up tokens on every prompt.

What to put in CLAUDE.md:

  • Project overview — what it does, who uses it, key goals
  • Tech stack — language versions, frameworks, databases
  • Architecture notes — key design decisions, module structure
  • Coding standards — style guide, naming conventions, patterns to follow
  • Common commands — how to run tests, build, deploy
  • Key files — where important things live
  • What to avoid — patterns, packages, or approaches not to use

CLAUDE.md Example

# Project: OrderFlow API

## Overview
B2B order management API for e-commerce. Powers order intake, fulfillment routing, and status tracking.

## Stack
- Python 3.12 + FastAPI
- PostgreSQL 16 (SQLAlchemy 2.0 async)
- Redis 7 (caching + job queue)
- Docker + Kubernetes (GKE)

## Architecture
- src/api/ — route handlers (thin, no business logic)
- src/services/ — business logic layer
- src/models/ — SQLAlchemy ORM models
- src/repositories/ — DB query layer
- tests/ — pytest with async fixtures

## Coding Standards
- All functions have type hints and docstrings
- No raw SQL — use SQLAlchemy ORM only
- Async-first: all I/O must be async/await
- Error handling: raise domain exceptions, catch at route level
- No print() — use logging module with structured JSON logs

## Common Commands
```
make test          # Run pytest suite
make lint          # ruff + mypy
make run           # docker compose up
make migrate       # run alembic upgrade head
```

## Do NOT
- Add new dependencies without checking existing package list
- Use synchronous DB calls (breaks connection pool)
- Hardcode configuration (use environment variables via pydantic-settings)

Managing the Context Window

Claude Code sessions accumulate context over time. Signs the context is getting unwieldy:

  • Claude starts repeating itself or forgetting recent decisions
  • Responses become slower
  • Claude refers to files it read 20 messages ago as if current

Strategies to manage this:

# Option 1: Use /clear to start fresh
/clear
# Then give Claude a quick summary of where you are

# Option 2: Use compact mode (summarizes context automatically)
claude --compact

# Option 3: Task-scoped sessions
# Start a new claude session for each distinct task
# rather than one long session for everything

Using Claude for Code Review

Claude Code is excellent as a code reviewer. Effective review prompts:

# Review a specific function
> Review the calculate_discount() function in src/services/pricing.py
  Check for:
  1. Correctness — any logic bugs or edge cases?
  2. Performance — any obvious bottlenecks?
  3. Security — any injection or overflow risks?
  4. Style — consistent with the rest of the codebase?
  Be specific, cite line numbers.

# Review a PR diff
> Run 'git diff main...HEAD' and review all changes.
  Flag any issues that should block merging.
  Rate overall code quality: Ready / Needs Work / Major Issues.

# Security-focused review
> Read src/api/auth.py and check for common authentication vulnerabilities:
  OWASP Top 10 relevant to auth, timing attacks, token handling.
Best practice: Ask Claude to cite specific line numbers and explain why something is an issue, not just flag it. "Line 42: the password comparison uses == instead of hmac.compare_digest(), making it vulnerable to timing attacks" is far more useful than "security issue in auth."

Claude Code Docs

Part 1 — Create CLAUDE.md for a Sample Project

# Set up a sample project
mkdir review-lab && cd review-lab
git init

# Create a sample Python file with intentional issues
cat > app.py << 'EOF'
import sqlite3
import hashlib

def get_user(username):
    conn = sqlite3.connect("users.db")
    cursor = conn.cursor()
    # Fetch user from database
    result = cursor.execute(
        "SELECT * FROM users WHERE username = '" + username + "'"
    )
    return result.fetchone()

def check_password(stored_hash, provided_password):
    provided_hash = hashlib.md5(provided_password.encode()).hexdigest()
    if stored_hash == provided_hash:
        return True
    return False

def process_order(items):
    total = 0
    for item in items:
        price = item['price']
        qty = item['quantity']
        discount = item.get('discount', 0)
        total = total + (price * qty) - discount
    print("Order total:", total)
    return total

def validate_email(email):
    if "@" in email:
        return True
EOF

git add app.py && git commit -m "Initial app"
claude

Part 2 — Ask Claude to Create CLAUDE.md

> Look at this project and create a CLAUDE.md file appropriate for it.
  Include sections for: project overview, tech stack, coding standards,
  and any red flags you see in the current code that should be documented
  as patterns to avoid.

Part 3 — Code Review

> Review app.py completely. For each function:
  1. Rate severity of any issues: Critical / High / Medium / Low
  2. Explain what the issue is
  3. Show the corrected code inline

  Be exhaustive — this is a security review.

Expected findings Claude should catch

  • Critical: SQL injection in get_user() — string concatenation in query
  • Critical: MD5 for password hashing — use bcrypt/argon2 instead
  • High: == for password comparison — use hmac.compare_digest()
  • Medium: No type hints on any function
  • Medium: print() instead of logging
  • Low: Email validation too naive — only checks for "@"

Part 4 — Fix and Verify

> Fix all Critical and High severity issues. Show me the diff when done.
