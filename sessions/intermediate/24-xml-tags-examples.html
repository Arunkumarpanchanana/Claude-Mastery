XML Tags, Examples & Prompt Structure

Structure your prompts like a pro — XML tags help Claude parse complex context, and few-shot examples are the fastest way to transfer your intent.

Why XML Tags Work

Claude was trained on a massive amount of structured text including HTML, XML, and documentation. XML-style tags create unambiguous boundaries between sections of a prompt, making it much easier for Claude to parse:

  • Which part is the instruction vs. the data to process
  • Where examples begin and end
  • What is context vs. what is the task
  • Where user-provided content starts (important for injection prevention)

Common XML Tag Patterns

prompt = """
<instructions>
You are a customer support agent. Classify the following ticket
into exactly one category: billing, technical, feature-request, or other.
Return only the category label — nothing else.
</instructions>

<examples>
<example>
<ticket>I can't log into my account and I've reset my password twice.</ticket>
<category>technical</category>
</example>

<example>
<ticket>I was charged twice for my subscription this month.</ticket>
<category>billing</category>
</example>
</examples>

<ticket>{user_ticket}</ticket>
"""

Few-Shot Examples

Few-shot examples are input/output pairs that show Claude the exact pattern you want. They're the most efficient way to specify format, style, and behavior that's hard to describe in words.

Rules for good few-shot examples:

  • Use 2-5 examples — more isn't always better
  • Cover edge cases in your examples, not just the easy case
  • Make examples representative of your real input distribution
  • Use consistent formatting across all examples
  • Place examples before the actual input to classify/process

Wrapping User Content in Tags

When you inject user-provided content into a prompt, wrap it in a tag. This prevents prompt injection — if the user writes "ignore previous instructions", it's clearly just document content:

def summarize_document(doc_text: str) -> str:
    prompt = f"""Summarize the following document in 3 bullet points.

<document>
{doc_text}
</document>

Summary:"""
    response = client.messages.create(
        model="claude-haiku-4-5",
        max_tokens=256,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.content[0].text

Structured Prompt Template Pattern

A reusable template with clear sections for different components:

PROMPT_TEMPLATE = """<role>
{role}
</role>

<context>
{context}
</context>

<instructions>
{instructions}
</instructions>

<examples>
{examples}
</examples>

<input>
{user_input}
</input>"""


def build_prompt(role: str, context: str, instructions: str,
                 examples: str, user_input: str) -> str:
    return PROMPT_TEMPLATE.format(
        role=role,
        context=context,
        instructions=instructions,
        examples=examples,
        user_input=user_input
    )
Tip: XML tags are especially useful in system prompts where you need to separate multiple sections — persona, constraints, available tools, background knowledge, and output format can each have their own tag.

Tag Naming Conventions

There are no reserved tag names — use descriptive ones that map to the content. Common conventions:

  • <instructions> — what to do
  • <context> — background information
  • <document> or <text> — content to process
  • <example> — a single few-shot example
  • <examples> — container for all examples
  • <output_format> — format specification
  • <thinking> — where you want Claude to reason

Lab: Build a Prompt Template with XML Structure

Build a reusable ticket classifier that uses XML tags and few-shot examples.

Open in Colab 
"""
xml_prompt_lab.py — Few-shot classification with XML tags
"""
import anthropic

client = anthropic.Anthropic()

# --- Define examples ---
EXAMPLES = [
    {
        "input": "I was charged twice for my Pro subscription this month.",
        "output": '{"category": "billing", "urgency": "high"}'
    },
    {
        "input": "The export to CSV feature doesn't include the timestamp column.",
        "output": '{"category": "bug", "urgency": "medium"}'
    },
    {
        "input": "Would love to see a dark mode option in the settings.",
        "output": '{"category": "feature-request", "urgency": "low"}'
    },
    {
        "input": "I can't figure out how to add a team member to my workspace.",
        "output": '{"category": "support", "urgency": "low"}'
    },
]


def build_examples_xml(examples: list[dict]) -> str:
    """Convert example list to XML format."""
    parts = []
    for ex in examples:
        parts.append(f"""<example>
  <ticket>{ex['input']}</ticket>
  <classification>{ex['output']}</classification>
</example>""")
    return "\n".join(parts)


def classify_ticket(ticket: str) -> dict:
    """Classify a support ticket using XML-structured few-shot prompt."""
    examples_xml = build_examples_xml(EXAMPLES)

    prompt = f"""<instructions>
Classify the support ticket into one category: billing, bug, feature-request, or support.
Also assign urgency: high, medium, or low.
Return ONLY a JSON object: {{"category": "...", "urgency": "..."}}
No explanation. No markdown.
</instructions>

<examples>
{examples_xml}
</examples>

<ticket>
{ticket}
</ticket>"""

    import json
    response = client.messages.create(
        model="claude-haiku-4-5",
        max_tokens=64,
        temperature=0,
        messages=[{"role": "user", "content": prompt}]
    )

    return json.loads(response.content[0].text.strip())


# --- Test the classifier ---
test_tickets = [
    "My invoice shows $99 but I'm on the $49/month plan.",
    "The API endpoint /users returns a 500 error intermittently.",
    "It would be great if we could schedule reports to run weekly.",
    "How do I reset my password?",
    "You charged my card three times today and I need a refund immediately!",
]

print("Support Ticket Classifier")
print("=" * 50)
for ticket in test_tickets:
    result = classify_ticket(ticket)
    print(f"\nTicket  : {ticket[:60]}...")
    print(f"Category: {result['category']}")
    print(f"Urgency : {result['urgency']}")

Why this works better without XML

Try removing the XML tags and observe — Claude may misidentify where the examples end and the real input begins, especially if tickets contain phrases like "instructions" or "example".
