Prompt Caching — Rules & Implementation

Cut costs by up to 90% and reduce latency by caching your large system prompts and shared context — once set up, it's automatic.

35 min Intermediate Code Lab 5 Quiz Questions

What Is Prompt Caching?

Prompt caching lets you mark part of your prompt as "cacheable". The first time that content is processed, Anthropic stores the KV cache for those tokens server-side. Subsequent requests that begin with the same cached prefix get a cache hit — those tokens are processed at a significantly lower cost (typically ~90% discount) and with lower latency.

When caching saves you money: You have a large system prompt (1,000+ tokens of instructions, documents, or tools) that you send with every request. Without caching, you pay full price for those tokens each time. With caching, you pay once per 5-minute window.

The cache_control Parameter

Add "cache_control": {"type": "ephemeral"} to the content block you want to cache:

import anthropic

client = anthropic.Anthropic()

# Large system prompt (must be ≥ 1024 tokens to be cacheable)
LARGE_SYSTEM_PROMPT = """You are an expert Python developer assistant.
[... imagine 2000+ tokens of detailed instructions, coding standards,
     API documentation, and project context here ...]
"""

response = client.messages.create(
    model="claude-haiku-4-5",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": LARGE_SYSTEM_PROMPT,
            "cache_control": {"type": "ephemeral"}  # Cache this!
        }
    ],
    messages=[
        {"role": "user", "content": "How do I write a context manager in Python?"}
    ]
)

# Check if the cache was used
usage = response.usage
print(f"Input tokens           : {usage.input_tokens}")
print(f"Cache creation tokens  : {usage.cache_creation_input_tokens}")
print(f"Cache read tokens      : {usage.cache_read_input_tokens}")
# On cache hit: cache_read_input_tokens > 0, cache_creation = 0

The Rules of Prompt Caching

  • Minimum 1024 tokens to be eligible for caching — short content cannot be cached
  • 5-minute TTL — cache expires 5 minutes after the last request that used it. Each cache hit resets the timer.
  • Prefix matching — the cached content must appear at the start of the prompt, unchanged
  • Up to 4 cache breakpoints per request
  • Writing costs slightly more — the first request to create the cache has a small surcharge (~25%). Every subsequent cache hit saves ~90%.

What to Cache

  • Long system prompts with instructions, company context, or domain knowledge
  • Tool definitions that don't change between requests
  • Large documents that many user questions will reference
  • Few-shot examples that precede the actual user input

Caching in the Messages Array

You can also cache content within the messages array — useful for a long document at the start of the conversation:

long_document = "..." * 500  # A long document text

response = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "text",
                    "text": f"Here is the document to analyze:\n\n{long_document}",
                    "cache_control": {"type": "ephemeral"}
                },
                {
                    "type": "text",
                    "text": "What are the key themes in this document?"
                }
            ]
        }
    ]
)
Cache hit strategy: Keep cached content at the beginning of your prompt and never-changing. Put dynamic, per-user content (their specific question) after the cached section. The cache prefix must match exactly — any modification breaks the cache.

Lab: Implement Prompt Caching for a Long System Prompt

"""
prompt_caching_lab.py — Measure caching benefits
"""
import anthropic
import time

client = anthropic.Anthropic()

# Generate a large system prompt (~1500 tokens)
SYSTEM_PROMPT_BASE = """
You are an expert software architect specializing in distributed systems.
You have deep expertise in: microservices, event-driven architecture, CAP theorem,
distributed transactions, message queues, API design, database sharding, caching
strategies, load balancing, service discovery, circuit breakers, and observability.

You follow these principles:
1. Always consider failure modes before designing happy paths
2. Prefer simple solutions over clever ones
3. Design for the reader, not the writer — code is read 10x more than written
4. Measure before optimizing — use data, not intuition
5. Explicit is better than implicit

When reviewing code or designs, always check for:
- Security vulnerabilities (OWASP Top 10)
- Performance bottlenecks (N+1 queries, missing indexes, unnecessary round trips)
- Error handling completeness
- Observability (logging, metrics, tracing)
- Scalability limits

Your response format:
- Be direct and specific — no filler phrases
- Use bullet points for lists of issues
- Provide concrete examples when suggesting improvements
- Rate severity: Critical > High > Medium > Low

Project context:
- Tech stack: Python/FastAPI, PostgreSQL, Redis, RabbitMQ, Kubernetes
- Team size: 8 engineers
- Uptime requirement: 99.9% (8.7 hours downtime/year max)
- Traffic: 10k req/min at peak, expected to 10x in 18 months
- Compliance: SOC 2 Type II, GDPR

{additional_context}
"""

# Make it long enough to cache (>1024 tokens)
ADDITIONAL_CONTEXT = """
Current architecture decisions:
- All services communicate via REST (moving to gRPC for internal)
- Database per service pattern (no shared DBs)
- Eventual consistency preferred over strong consistency where possible
- All secrets managed via HashiCorp Vault
- Observability stack: Datadog APM, structured JSON logging, OpenTelemetry
- Deployment: GitOps via ArgoCD, blue/green deployments
- All changes go through code review + automated tests before production
""" * 3  # Repeat to ensure we exceed 1024 tokens

SYSTEM_PROMPT = SYSTEM_PROMPT_BASE.format(additional_context=ADDITIONAL_CONTEXT)
print(f"System prompt length: ~{len(SYSTEM_PROMPT.split())} words")


def make_request(question: str, use_cache: bool) -> dict:
    """Make a request with or without caching."""
    system_content = {"type": "text", "text": SYSTEM_PROMPT}
    if use_cache:
        system_content["cache_control"] = {"type": "ephemeral"}

    start = time.time()
    response = client.messages.create(
        model="claude-haiku-4-5",
        max_tokens=256,
        system=[system_content],
        messages=[{"role": "user", "content": question}]
    )
    latency = (time.time() - start) * 1000

    return {
        "latency_ms": latency,
        "input_tokens": response.usage.input_tokens,
        "cache_creation": getattr(response.usage, "cache_creation_input_tokens", 0),
        "cache_read": getattr(response.usage, "cache_read_input_tokens", 0),
        "output_tokens": response.usage.output_tokens,
        "text": response.content[0].text[:100]
    }


QUESTIONS = [
    "What's the biggest risk in our current architecture?",
    "How should we handle database migrations in our microservices?",
    "What observability metrics should we track for our API gateway?",
]

print("\n=== WITHOUT CACHING ===")
for q in QUESTIONS:
    result = make_request(q, use_cache=False)
    print(f"Q: {q[:50]}...")
    print(f"  Latency: {result['latency_ms']:.0f}ms | Tokens: {result['input_tokens']} in")
    print()

print("\n=== WITH CACHING (first request creates cache) ===")
for i, q in enumerate(QUESTIONS):
    result = make_request(q, use_cache=True)
    print(f"Q: {q[:50]}...")
    print(f"  Latency   : {result['latency_ms']:.0f}ms")
    print(f"  Cache miss: {result['cache_creation']} tokens created")
    print(f"  Cache hit : {result['cache_read']} tokens read from cache")
    print()
