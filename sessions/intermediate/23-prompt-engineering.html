Prompt Engineering — Clear & Direct

The difference between a mediocre and excellent Claude response is usually the prompt — learn the techniques that actually move the needle.

1. Be Specific — Eliminate Ambiguity

Vague prompts produce vague responses. Every word of ambiguity in your prompt is a decision you're outsourcing to Claude. Be explicit about what you want.

VagueSpecific
"Summarize this article.""Summarize this article in exactly 3 bullet points. Each point max 20 words. Focus on business impact."
"Write some code.""Write a Python function that takes a list of integers and returns the top 3 values sorted descending. Include type hints and a docstring."
"Make this better.""Rewrite this paragraph to be more concise. Remove filler words. Target: under 50 words. Keep all factual claims."

2. Task Decomposition

Complex requests broken into steps get better results. Instead of one massive prompt, guide Claude step by step within the prompt:

DECOMPOSED_PROMPT = """
Analyze the following customer review. Complete each step in order:

Step 1: Identify the main product mentioned.
Step 2: List all positive aspects mentioned (bullet points).
Step 3: List all negative aspects mentioned (bullet points).
Step 4: Rate the overall sentiment: Positive / Neutral / Negative.
Step 5: Suggest one product improvement based on the feedback.

Review: {review_text}
"""

3. Role Assignment

Assigning Claude a specific expert role improves answer quality for domain tasks. The role sets implicit context about vocabulary, depth, and assumptions.

system = """You are a senior backend engineer with 10 years of experience
in distributed systems. You give direct, technical answers. You do not explain
basics unless asked. When reviewing code, you focus on correctness, performance,
and security — in that order."""
Role tip: Be specific about the expertise level and priorities. "You are a helpful assistant" is weak. "You are a tax attorney specializing in US small business law" sets real constraints Claude will follow.

4. Output Format Instructions

Tell Claude exactly what format you expect for the response:

format_instructions = """
Respond using this exact structure:
HEADLINE: [one sentence summary]
DETAILS: [2-3 sentence explanation]
ACTION: [one specific next step for the user]

Do not use markdown. Do not add any text outside this structure.
"""

5. Chain-of-Thought Prompting

For reasoning tasks, asking Claude to "think step by step" improves accuracy by making it work through the problem before committing to an answer:

cot_prompt = """
A train leaves City A at 9:00 AM traveling at 60 mph.
A second train leaves City B (300 miles away) at 10:00 AM traveling at 90 mph toward City A.
At what time do they meet?

Think through this step by step before giving your final answer.
"""

6. Use Positive Instructions

Tell Claude what TO do, not just what NOT to do. Negative instructions (don't, never, avoid) are harder to follow reliably:

Negative (avoid)Positive (prefer)
"Don't use jargon.""Use plain English understandable by a non-technical reader."
"Don't be too long.""Limit your response to 100 words."
"Don't give generic advice.""Give advice specific to Python web APIs built with FastAPI."

7. Context Before Task

Place background information and context before the task instruction. Claude reads top-to-bottom and context at the end is often processed less reliably:

# Good: Context then task
prompt = """
Context: We are building a B2B SaaS product for accounting firms.
Our users are CPAs with 5-15 years experience. They are comfortable with Excel.
The product must comply with SOC 2 Type II.

Task: Write a one-paragraph product description for our homepage hero section.
"""

# Worse: Task then context
prompt = """
Write a one-paragraph product description.
Context: B2B SaaS for accountants, SOC 2, Excel users...
"""

Lab: Rewrite Bad Prompts and Compare Outputs

See the measurable difference that good prompting makes by running weak and strong versions of the same request side-by-side.

Open in Colab 
"""
prompt_comparison.py — Compare weak vs. strong prompts
"""
import anthropic

client = anthropic.Anthropic()

def compare(weak_prompt: str, strong_prompt: str, label: str) -> None:
    """Run both prompts and print outputs for comparison."""
    print(f"\n{'='*60}")
    print(f"TEST: {label}")

    for title, prompt in [("WEAK", weak_prompt), ("STRONG", strong_prompt)]:
        response = client.messages.create(
            model="claude-haiku-4-5",
            max_tokens=256,
            temperature=0.3,
            messages=[{"role": "user", "content": prompt}]
        )
        text = response.content[0].text.strip()
        print(f"\n--- {title} PROMPT ---")
        print(f"Prompt: {prompt[:80]}...")
        print(f"Output ({len(text)} chars):\n{text}")


# Test 1: Summarization
compare(
    weak_prompt="Summarize this: Python is a high-level, interpreted programming language known for its simple syntax, readability, and versatility. It supports multiple programming paradigms including procedural, object-oriented, and functional programming.",
    strong_prompt="Summarize the following text in exactly 2 bullet points. Each bullet max 15 words. Focus on what makes Python distinctive:\n\nPython is a high-level, interpreted programming language known for its simple syntax, readability, and versatility. It supports multiple programming paradigms including procedural, object-oriented, and functional programming.",
    label="Summarization specificity"
)

# Test 2: Code generation
compare(
    weak_prompt="Write a function to check if a number is prime.",
    strong_prompt="Write a Python function is_prime(n: int) -> bool. Requirements: handle edge cases (n < 2 returns False), use trial division up to sqrt(n), include type hints, and add a 1-line docstring. No imports needed.",
    label="Code generation precision"
)

# Test 3: Chain of thought
compare(
    weak_prompt="If I have 3 apples and give away 2, then buy 4, then eat 1, how many do I have?",
    strong_prompt="Solve this step by step, showing your work at each stage:\nI start with 3 apples. I give away 2. I buy 4 more. I eat 1. How many do I have at the end?",
    label="Chain-of-thought reasoning"
)

# Test 4: Role + format
compare(
    weak_prompt="What's wrong with this SQL: SELECT * FROM users WHERE id = '" + "1 OR '1'='1" + "'",
    strong_prompt="""You are a database security expert. Analyze this SQL for security vulnerabilities.

Format your response as:
VULNERABILITY: [name of the issue]
SEVERITY: [Critical/High/Medium/Low]
EXPLANATION: [1 sentence]
FIX: [corrected SQL]

SQL: SELECT * FROM users WHERE id = '1 OR '1'='1'""",
    label="Role + structured output"
)
