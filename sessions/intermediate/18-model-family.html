Claude Model Family Overview

Haiku, Sonnet, Opus — pick the right model for every job and stop overpaying for capability you don't need.

30 min Intermediate Model Comparison 5 Quiz Questions

The Three Model Tiers

Anthropic ships Claude models in three performance tiers — Haiku, Sonnet, and Opus — optimized for different positions on the speed/cost/capability curve. Choosing the right tier is your first API decision and directly impacts user experience and your bill.

Mental model: Think of Haiku as a sports car (fast, efficient, not the most powerful), Sonnet as an SUV (balanced, does almost everything well), and Opus as a heavy-duty truck (maximum capability, higher cost, use when nothing else will do).

Haiku — Speed and Cost

Haiku is Claude's fastest and most affordable model. It excels at:

  • Real-time applications — chatbots, autocomplete, instant classification
  • High-volume pipelines — processing thousands of documents per hour
  • Simple extraction tasks — pulling entities, categorizing sentiment, formatting data
  • User-facing latency-sensitive features — anywhere sub-second response matters

Haiku won't win on complex reasoning, nuanced writing, or ambiguous multi-step tasks — but for clear, well-specified work it performs remarkably well at a fraction of the cost.

Sonnet — The Daily Driver

Sonnet is the model most developers reach for first. It offers a strong balance of intelligence, speed, and cost. Use Sonnet for:

  • Code generation and review
  • Summarization of moderate-length documents
  • Customer support with nuance
  • Agentic tasks that require some reasoning
  • Most production API use cases

Claude 3.5 Sonnet and Claude 3.7 Sonnet represent major leaps in coding ability. If you're building a coding assistant, start with the latest Sonnet.

Opus — Maximum Intelligence

Opus is reserved for tasks that require the deepest reasoning, longest context retention, and highest accuracy. Deploy Opus when:

  • Accuracy is more important than cost
  • Tasks require multi-step logical reasoning over long documents
  • You need research synthesis across complex material
  • Failures are expensive (legal, medical, financial analysis)

Tip: Always use the latest model in a tier unless you have a reason (cost budget, specific benchmark, existing evals). Anthropic maintains backwards-compatible aliases like claude-sonnet-4-5 so pinning by full model ID gives you stability.

Model Selection Strategy

Follow this decision tree when selecting a model:

  1. Start with Sonnet. It handles 80% of tasks well.
  2. Switch to Haiku if latency or cost is the bottleneck and task quality meets the bar.
  3. Upgrade to Opus only when Sonnet's accuracy is measurably insufficient. Run evals to prove this.
  4. Use routing — send simple queries to Haiku, complex to Sonnet/Opus — for the best cost/quality ratio at scale.

Pricing Mental Model

Prices shift with each generation release, but the relative ratios stay roughly stable. As a rule of thumb:

  • Haiku costs ~10-20x less than Opus per token
  • Sonnet sits in between, often 3-5x less than Opus
  • For a million-token workload, this difference is meaningful budget

Always check the official pricing page for current rates before committing to a production architecture.

Context Windows

All modern Claude models support a 200K token context window — roughly 150,000 words or a full novel. This means you rarely hit context limits in practice. The main constraint is cost: longer prompts cost more, so trimming context still matters at scale.

Lab: Compare Models Side by Side

Run the same prompt through Haiku and Sonnet, then measure the latency and token usage difference yourself.

Open in Colab 
import anthropic
import time

client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY from env

PROMPT = "Explain the tradeoffs between SQL and NoSQL databases in 3 bullet points."

models = [
    "claude-haiku-4-5",
    "claude-sonnet-4-5",
]

for model in models:
    start = time.time()
    response = client.messages.create(
        model=model,
        max_tokens=256,
        messages=[{"role": "user", "content": PROMPT}]
    )
    elapsed = time.time() - start

    print(f"\n=== {model} ===")
    print(f"Latency  : {elapsed:.2f}s")
    print(f"In tokens: {response.usage.input_tokens}")
    print(f"Out tokens: {response.usage.output_tokens}")
    print("Response:")
    print(response.content[0].text)

What to observe

  • Wall-clock latency difference (Haiku is typically 2-4x faster for short outputs)
  • Quality difference — does Sonnet add more nuance?
  • Token counts are identical for the same input; output length may differ
