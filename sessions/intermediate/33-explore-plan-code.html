The Explore → Plan → Code → Commit Flow

The four-phase workflow that makes Claude Code shine — use it for any feature or bug fix to get better results with fewer mistakes.

45 min Intermediate Code Lab 5 Quiz Questions

The Four-Phase Workflow

The most effective way to use Claude Code for non-trivial tasks isn't to just fire off a single prompt. The four-phase workflow forces Claude to understand before acting:

PhaseWhat happensPrompt signal
1. ExploreClaude reads relevant code, understands structure"Read/explore/understand..."
2. PlanClaude proposes an approach before touching files"Plan/outline/describe how you'd..."
3. CodeClaude implements the plan iteratively"Now implement..."
4. CommitReview, test, then commit"Run tests, then commit with..."

Phase 1 — Explore

Before asking Claude to write any code, ask it to understand the relevant part of the codebase:

# In Claude Code terminal:
> Explore the authentication module in src/auth/. Read the relevant files and explain:
  1. How users are currently authenticated
  2. Where session tokens are stored
  3. What the token expiry logic looks like
  Don't make any changes yet.

This phase gives Claude the context it needs to make correct, consistent changes instead of guessing at patterns.

Phase 2 — Plan

With context loaded, ask Claude to propose a plan before writing code:

> Based on what you've read, plan how you would add refresh token support.
  List:
  - Which files you'll modify
  - What new files you'll create (if any)
  - The changes at a function/class level
  - Any edge cases to handle
  Wait for my approval before implementing.
Why plan first? Planning catches architectural mistakes before they're in code. It also gives you a checklist to verify the implementation matches the intention.

Phase 3 — Code (Iteratively)

Once you've approved the plan, ask Claude to implement it. Do it in steps — don't ask for everything at once:

> Good plan. Start with step 1: add the refresh token model to models.py.
  Don't move on to step 2 until I confirm this looks right.

# After review:
> This looks good. Now implement step 2: the refresh endpoint in auth/routes.py.

Git Integration

Claude Code has full git access. Use it throughout:

> What does git log show for the last 5 commits to auth/routes.py?

> Create a new branch called feature/refresh-tokens before we start.

> Show me a git diff of all changes so far.

> Run the tests and if they pass, commit with message: "feat: add refresh token support"

Phase 4 — Commit

Always run tests before committing. Ask Claude to handle this:

> Run all tests in the tests/ directory. If all pass, create a git commit with a conventional commit message summarizing the changes. If any fail, fix them first.

When to Commit

  • After each logically complete unit of work (not after every file edit)
  • Before switching to a different task
  • After tests pass — never commit broken code
  • With descriptive messages following your project's convention

Lab: Build a Small Python CLI Tool End-to-End

Use the full Explore → Plan → Code → Commit flow with Claude Code to build a word frequency counter CLI.

Claude Code Docs

Setup

mkdir wordfreq-cli && cd wordfreq-cli
git init
echo "# Word Frequency CLI" > README.md
git add . && git commit -m "Initial commit"
claude

Phase 1 — Explore

> We're building a Python CLI tool that counts word frequencies in a text file.
  Before writing any code, explore the current project structure and tell me:
  1. What files exist
  2. What Python version is available
  3. Whether pytest is installed
  Don't write any code yet.

Phase 2 — Plan

> Plan the implementation of wordfreq.py - a CLI tool that:
  - Takes a filename as a CLI argument
  - Reads the file
  - Counts word frequencies (case-insensitive, strips punctuation)
  - Prints the top N words (N is a flag, default 10)
  - Shows a simple bar chart using ASCII characters

  Include:
  - List of functions to create
  - The CLI interface (argparse)
  - Error handling plan

  Wait for my approval.

Phase 3 — Code

> Implement the plan. Create wordfreq.py with all the described functionality.

# After seeing the code:
> Now create tests/test_wordfreq.py with at least 5 test cases covering:
  - Basic word counting
  - Case insensitivity
  - Punctuation stripping
  - Empty file handling
  - Top N filtering

# After seeing tests:
> Run the tests with pytest -v.

Phase 4 — Commit

> If all tests pass, commit the implementation with a conventional commit message.
  Then show me how to use the tool with an example.

Expected final structure

wordfreq-cli/
├── wordfreq.py        # Main CLI script
├── tests/
│   └── test_wordfreq.py
└── README.md

Example usage (Claude Code generates this too)

python wordfreq.py sample.txt --top 5
