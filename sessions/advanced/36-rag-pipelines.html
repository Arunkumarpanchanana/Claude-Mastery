RAG Pipelines — Chunking & Embeddings

Build retrieval-augmented generation from scratch: chunk documents intelligently, embed them into vector space, and retrieve relevant context for Claude.

What is RAG and Why Does It Matter?

Large language models like Claude are trained on data up to a cutoff date and have no knowledge of your private documents, internal wikis, or real-time information. Retrieval-Augmented Generation (RAG) solves this by dynamically fetching relevant context at query time and injecting it into the prompt before Claude generates a response.

Instead of stuffing an entire document corpus into the context window (expensive and often beyond context limits), RAG retrieves only the most relevant passages. This approach is faster, cheaper, more accurate, and scales to millions of documents.

The core insight: Claude's 200K context window is powerful, but a well-designed RAG system lets you query across millions of documents — far beyond any context window. RAG is how production AI apps handle knowledge at scale.

The Full RAG Flow

RAG has two distinct phases: an offline indexing phase (run once or periodically) and an online query phase (run on every user request).

Document Chunking Strategies

Chunking is the most underrated decision in a RAG pipeline. Chunks that are too large include irrelevant text; chunks that are too small lose context. The right strategy depends on your document type.

1. Fixed-Size Chunking

Split documents into chunks of exactly N characters or tokens, with an optional overlap. Simple, fast, and works as a baseline.

def fixed_size_chunk(text: str, chunk_size: int = 512, overlap: int = 64) -> list[str]:
    """Split text into fixed-size chunks with overlap."""
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start += chunk_size - overlap  # slide forward with overlap
    return chunks
Pitfall: Fixed chunking can split mid-sentence or mid-paragraph, breaking semantic coherence. Always add overlap (typically 10–15% of chunk size) so sentences at boundaries appear in two chunks.

2. Recursive / Semantic Chunking

Try to split at natural boundaries: paragraphs first, then sentences, then words. LangChain's RecursiveCharacterTextSplitter implements this pattern well.

def recursive_chunk(text: str, chunk_size: int = 512, overlap: int = 64) -> list[str]:
    """Recursively split at natural boundaries."""
    separators = ["\n\n", "\n", ". ", " ", ""]

    def split_with_separator(text, separators, chunk_size, overlap):
        if not separators:
            return [text[i:i+chunk_size] for i in range(0, len(text), chunk_size - overlap)]

        sep = separators[0]
        splits = text.split(sep)

        chunks = []
        current = ""
        for split in splits:
            candidate = current + (sep if current else "") + split
            if len(candidate) <= chunk_size:
                current = candidate
            else:
                if current:
                    chunks.append(current)
                if len(split) > chunk_size:
                    # Recursively split this large piece
                    sub = split_with_separator(split, separators[1:], chunk_size, overlap)
                    chunks.extend(sub)
                    current = ""
                else:
                    current = split
        if current:
            chunks.append(current)
        return chunks

    return split_with_separator(text, separators, chunk_size, overlap)

3. Document-Structure-Aware Chunking

For structured documents (Markdown, HTML, code), split by headers or logical sections. This keeps each chunk topically coherent.

import re

def markdown_chunk(text: str) -> list[dict]:
    """Split markdown by headers, preserving section structure."""
    sections = re.split(r'\n(?=#{1,3} )', text)
    chunks = []
    for section in sections:
        if not section.strip():
            continue
        # Extract header as metadata
        lines = section.strip().split('\n')
        header = lines[0].lstrip('#').strip() if lines[0].startswith('#') else "Introduction"
        chunks.append({
            "content": section.strip(),
            "metadata": {"header": header, "length": len(section)}
        })
    return chunks

Text Embeddings

An embedding model converts text into a dense vector of numbers (typically 384–3072 dimensions). Semantically similar text produces similar vectors — this is what powers similarity search.

Option 1: sentence-transformers (local, free)

from sentence_transformers import SentenceTransformer
import numpy as np

# Load a small but capable model (free, runs locally)
model = SentenceTransformer('all-MiniLM-L6-v2')  # 384-dimensional embeddings

texts = [
    "Claude is an AI assistant made by Anthropic.",
    "Retrieval augmented generation improves LLM accuracy.",
    "The capital of France is Paris."
]

# Embed all texts at once (batched for efficiency)
embeddings = model.encode(texts, normalize_embeddings=True)
print(f"Shape: {embeddings.shape}")  # (3, 384)

# Cosine similarity between first two
similarity = np.dot(embeddings[0], embeddings[1])
print(f"Similarity (Claude vs RAG): {similarity:.3f}")  # ~0.3
similarity2 = np.dot(embeddings[0], embeddings[2])
print(f"Similarity (Claude vs Paris): {similarity2:.3f}")  # ~0.1

Option 2: OpenAI / Anthropic-compatible Embeddings API

import anthropic
import numpy as np

# Note: Anthropic doesn't provide embeddings directly; use voyage-ai (Anthropic-recommended)
# or OpenAI's text-embedding-3-small for production
import voyageai

vo = voyageai.Client()  # uses VOYAGE_API_KEY

texts = ["What is RAG?", "Retrieval augmented generation explained"]
result = vo.embed(texts, model="voyage-3-lite", input_type="document")

embeddings = np.array(result.embeddings)
print(f"Dimensions: {embeddings.shape[1]}")  # 512 for voyage-3-lite

Vector Stores

A vector store indexes your embeddings for fast approximate nearest-neighbor (ANN) search.

FAISS (Facebook AI Similarity Search)

FAISS is the gold standard for in-memory vector search. No server required — it's a library.

import faiss
import numpy as np

# Create a flat (exact) index for small datasets
d = 384  # embedding dimension
index = faiss.IndexFlatIP(d)  # Inner Product = cosine similarity if normalized

# Add embeddings to the index
embeddings = np.random.randn(1000, d).astype('float32')
faiss.normalize_L2(embeddings)  # normalize for cosine
index.add(embeddings)
print(f"Total vectors: {index.ntotal}")  # 1000

# Query
query = np.random.randn(1, d).astype('float32')
faiss.normalize_L2(query)
distances, indices = index.search(query, k=5)  # top-5 results
print(f"Top-5 indices: {indices[0]}")
print(f"Top-5 scores:  {distances[0]}")

ChromaDB (persistent, with metadata filtering)

ChromaDB adds persistence, metadata, and a simple API — great for prototypes and small production apps.

import chromadb
from chromadb.utils import embedding_functions

# Create an in-memory client (use chromadb.PersistentClient for disk)
client = chromadb.Client()
ef = embedding_functions.SentenceTransformerEmbeddingFunction(
    model_name="all-MiniLM-L6-v2"
)

collection = client.create_collection("my_docs", embedding_function=ef)

# Add documents
collection.add(
    documents=["RAG improves accuracy", "Claude is safe by design", "FAISS is fast"],
    metadatas=[{"source": "doc1"}, {"source": "doc2"}, {"source": "doc3"}],
    ids=["id1", "id2", "id3"]
)

# Query
results = collection.query(query_texts=["How does RAG help?"], n_results=2)
print(results['documents'])   # [['RAG improves accuracy', 'Claude is safe by design']]
print(results['distances'])   # similarity scores

Choosing the Right Tools

FAISS

  • Best: high-performance, large scale
  • In-memory (add your own persistence)
  • Supports GPU acceleration
  • No metadata filtering built-in

ChromaDB

  • Best: rapid prototyping
  • Persistent storage out of box
  • Rich metadata filtering
  • HTTP server mode available

Pinecone / Weaviate

  • Best: production, managed service
  • Fully managed, auto-scaling
  • Advanced filtering and namespacing
  • Cost scales with data size

Lab: Build a Basic RAG Pipeline

In this lab you will chunk a sample document, embed the chunks with sentence-transformers, store them in FAISS, and retrieve relevant passages to answer a question with Claude.

Prerequisites

pip install anthropic sentence-transformers faiss-cpu numpy

Step 1: Prepare and Chunk a Document

import re

DOCUMENT = """
# Introduction to Transformers

Transformers are a neural network architecture introduced in the paper
"Attention Is All You Need" (Vaswani et al., 2017). They use a mechanism
called self-attention to weigh the relevance of different parts of the input.

## Why Transformers Replaced RNNs

Recurrent Neural Networks (RNNs) process sequences one token at a time,
making them slow to train on long sequences. Transformers process all tokens
simultaneously using attention, enabling parallelization on modern GPUs.
This made training on massive datasets feasible for the first time.

## Self-Attention Explained

Self-attention computes a weighted sum of all token representations in a
sequence. For each token, it asks: "Which other tokens are relevant to me?"
The weights are computed via dot products between query and key vectors.
Higher dot products mean more relevance.

## BERT vs GPT Architectures

BERT uses a bidirectional encoder — it can look at tokens from both left
and right. It's ideal for classification and understanding tasks.
GPT uses a causal (left-to-right) decoder, making it ideal for text
generation. Claude is based on a decoder-only transformer, like GPT.

## Context Windows

The context window is the maximum number of tokens a transformer can
process at once. Claude supports up to 200,000 tokens — among the largest
in the industry. Longer context windows allow working with entire codebases
or books in a single session.
"""

def recursive_chunk(text: str, chunk_size: int = 300, overlap: int = 50) -> list[str]:
    separators = ["\n\n", "\n", ". ", " "]

    def _split(text, seps):
        if not seps or len(text) <= chunk_size:
            return [text] if text.strip() else []
        sep = seps[0]
        parts = text.split(sep)
        chunks, current = [], ""
        for part in parts:
            candidate = current + (sep if current else "") + part
            if len(candidate) <= chunk_size:
                current = candidate
            else:
                if current:
                    chunks.append(current.strip())
                current = part if len(part) <= chunk_size else ""
                if len(part) > chunk_size:
                    chunks.extend(_split(part, seps[1:]))
        if current.strip():
            chunks.append(current.strip())
        return chunks

    chunks = _split(text, separators)
    # Add overlap
    overlapped = []
    for i, chunk in enumerate(chunks):
        if i > 0:
            prev_words = chunks[i-1].split()[-overlap//5:]
            prefix = " ".join(prev_words)
            overlapped.append(prefix + " " + chunk)
        else:
            overlapped.append(chunk)
    return overlapped

chunks = recursive_chunk(DOCUMENT)
print(f"Created {len(chunks)} chunks")
for i, c in enumerate(chunks):
    print(f"\n--- Chunk {i+1} ({len(c)} chars) ---")
    print(c[:100] + "...")

Step 2: Embed Chunks and Build FAISS Index

import numpy as np
import faiss
from sentence_transformers import SentenceTransformer

# Load embedding model (downloads ~90MB on first run)
embedder = SentenceTransformer('all-MiniLM-L6-v2')

# Embed all chunks
print("Embedding chunks...")
embeddings = embedder.encode(chunks, normalize_embeddings=True, show_progress_bar=True)
embeddings = embeddings.astype('float32')

# Build FAISS index
d = embeddings.shape[1]  # 384 dimensions
index = faiss.IndexFlatIP(d)  # Inner product = cosine similarity (on normalized vecs)
index.add(embeddings)
print(f"Index built with {index.ntotal} vectors of dimension {d}")

Step 3: Retrieve Relevant Chunks

def retrieve(query: str, k: int = 3) -> list[dict]:
    """Retrieve top-k most relevant chunks for a query."""
    q_emb = embedder.encode([query], normalize_embeddings=True).astype('float32')
    distances, indices = index.search(q_emb, k)

    results = []
    for dist, idx in zip(distances[0], indices[0]):
        if idx >= 0:
            results.append({
                "chunk": chunks[idx],
                "score": float(dist),
                "index": int(idx)
            })
    return results

# Test retrieval
query = "How does self-attention work?"
results = retrieve(query, k=3)
print(f"Query: {query}\n")
for r in results:
    print(f"Score: {r['score']:.3f} | Chunk {r['index']}")
    print(r['chunk'][:150])
    print()

Step 4: Feed Context to Claude

import anthropic

client = anthropic.Anthropic()  # uses ANTHROPIC_API_KEY

def rag_query(user_question: str) -> str:
    """Full RAG pipeline: retrieve + generate."""
    # 1. Retrieve relevant context
    retrieved = retrieve(user_question, k=3)
    context_text = "\n\n---\n\n".join([r["chunk"] for r in retrieved])

    # 2. Build augmented prompt
    system = """You are a helpful assistant. Answer questions using ONLY the provided context.
If the context doesn't contain enough information, say so clearly.
Always cite which part of the context you used."""

    user_prompt = f"""Context:
{context_text}

Question: {user_question}"""

    # 3. Call Claude
    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=512,
        system=system,
        messages=[{"role": "user", "content": user_prompt}]
    )
    return response.content[0].text

# Test it!
questions = [
    "How does self-attention work?",
    "Why were transformers better than RNNs?",
    "What is Claude's context window size?"
]

for q in questions:
    print(f"\nQ: {q}")
    print(f"A: {rag_query(q)}")
    print("-" * 60)
You built a working RAG pipeline! The key steps were: chunk the document, embed chunks, index with FAISS, embed the query at runtime, retrieve top-K, and pass context to Claude. This same pattern powers production RAG systems at scale.
