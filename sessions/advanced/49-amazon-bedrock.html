Claude on Amazon Bedrock

Access Claude through Amazon Bedrock with boto3 — understand IAM setup, cross-region inference, Bedrock-specific features, and how it differs from the Anthropic SDK.

45 min Advanced Code Lab 5 Quiz Questions

What is Amazon Bedrock?

Amazon Bedrock is AWS's fully managed foundation model service. It provides access to Claude (Anthropic), Titan (Amazon), Llama (Meta), Mistral, and other models through a unified AWS API. Instead of calling Anthropic's API directly, enterprise AWS customers can access Claude through their existing AWS infrastructure, IAM permissions, VPC, and billing.

Who uses Bedrock? Companies already deep in AWS who want: (1) data to stay within their AWS account, (2) IAM-based access control instead of API keys, (3) unified billing through AWS, (4) compliance with AWS enterprise agreements, or (5) integration with other AWS services like S3, Lambda, and SageMaker.

IAM Setup

Unlike the Anthropic SDK which uses API keys, Bedrock uses IAM roles and policies:

# IAM policy needed to call Claude via Bedrock:
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel",
                "bedrock:InvokeModelWithResponseStream"
            ],
            "Resource": [
                "arn:aws:bedrock:*::foundation-model/anthropic.claude-opus-4-5-*",
                "arn:aws:bedrock:*::foundation-model/anthropic.claude-3-*"
            ]
        }
    ]
}

# Attach this policy to your IAM user, role, or service account.
# Configure credentials with:
# aws configure  (sets ~/.aws/credentials)
# or use environment variables:
# AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN

Making Your First Bedrock Call

import boto3
import json

# Create Bedrock client — uses ~/.aws/credentials or env vars automatically
bedrock = boto3.client(
    service_name="bedrock-runtime",
    region_name="us-east-1"  # Claude is available in us-east-1, us-west-2, eu-central-1, etc.
)

# Model IDs follow Bedrock's convention (different from Anthropic SDK)
MODEL_ID = "anthropic.claude-opus-4-5-20251101-v1:0"
# Format: anthropic.{model-family}-{version}:0

# Bedrock uses the Messages API format, but wrapped in Bedrock's invoke_model
request_body = {
    "anthropic_version": "bedrock-2023-05-31",  # Required for all Bedrock Claude calls
    "max_tokens": 1024,
    "messages": [
        {
            "role": "user",
            "content": "Explain the difference between Bedrock and the Anthropic API in one paragraph."
        }
    ]
}

response = bedrock.invoke_model(
    modelId=MODEL_ID,
    body=json.dumps(request_body),
    contentType="application/json",
    accept="application/json"
)

# Parse response
response_body = json.loads(response["body"].read())
print(response_body["content"][0]["text"])
print(f"\nInput tokens: {response_body['usage']['input_tokens']}")
print(f"Output tokens: {response_body['usage']['output_tokens']}")

Bedrock vs Anthropic SDK Differences

Anthropic SDK

import anthropic
client = anthropic.Anthropic()
response = client.messages.create(
    model="claude-opus-4-5",
    max_tokens=1024,
    messages=[...]
)
text = response.content[0].text

Bedrock boto3

import boto3, json
client = boto3.client("bedrock-runtime")
resp = client.invoke_model(
    modelId="anthropic.claude-opus-4-5-...",
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 1024,
        "messages": [...]
    })
)
body = json.loads(resp["body"].read())
text = body["content"][0]["text"]

Streaming with Bedrock

import boto3
import json

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")

# Streaming uses invoke_model_with_response_stream
response = bedrock.invoke_model_with_response_stream(
    modelId="anthropic.claude-opus-4-5-20251101-v1:0",
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 1024,
        "stream": True,
        "messages": [{"role": "user", "content": "Write a haiku about cloud computing."}]
    })
)

# Stream events
for event in response["body"]:
    chunk = json.loads(event["chunk"]["bytes"])
    if chunk.get("type") == "content_block_delta":
        print(chunk["delta"].get("text", ""), end="", flush=True)
    elif chunk.get("type") == "message_stop":
        print(f"\n\nStop reason: {chunk.get('amazon-bedrock-invocationMetrics', {})}")

Cross-Region Inference

When a region's Claude capacity is exhausted, cross-region inference automatically routes requests to another AWS region with available capacity — reducing throttling for high-volume applications:

import boto3, json

# Use the cross-region inference profile instead of a region-specific model ID
# Format: {region-prefix}.{model-id}
CROSS_REGION_MODEL_ID = "us.anthropic.claude-opus-4-5-20251101-v1:0"
# "us." prefix = can use any US region (us-east-1, us-west-2)
# "eu." prefix = can use any EU region

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")

response = bedrock.invoke_model(
    modelId=CROSS_REGION_MODEL_ID,  # Will auto-route if us-east-1 is busy
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 512,
        "messages": [{"role": "user", "content": "Hello!"}]
    })
)

print(json.loads(response["body"].read())["content"][0]["text"])

Bedrock-Specific Features

  • Guardrails: Apply content filtering, PII redaction, and topic blocking at the infrastructure level — bypasses Claude's direct API, applies to any model on Bedrock.
  • Knowledge Bases: Bedrock's managed RAG service — upload documents to S3, Bedrock handles chunking, embedding, and retrieval.
  • Agents for Bedrock: AWS-native agent framework that works with Lambda functions as tools.
  • Model Evaluation: Run automated evaluations of Claude responses using Bedrock's eval framework.
  • VPC endpoints: Keep all traffic within your VPC — never touches the public internet.

Lab: Bedrock API Call vs Anthropic SDK — Side by Side

Call Claude with identical prompts using both the Anthropic SDK and the Bedrock boto3 client. Compare the APIs, response structure, and latency.

import time
import json

# ── Part 1: Anthropic SDK Call ─────────────────────────────────────────────────
import anthropic

def call_anthropic_sdk(prompt: str) -> dict:
    """Call Claude via the Anthropic SDK."""
    client = anthropic.Anthropic()  # Uses ANTHROPIC_API_KEY

    start = time.time()
    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=300,
        system="You are a helpful assistant. Be concise.",
        messages=[{"role": "user", "content": prompt}]
    )
    elapsed = time.time() - start

    return {
        "source": "Anthropic SDK",
        "text": response.content[0].text,
        "input_tokens": response.usage.input_tokens,
        "output_tokens": response.usage.output_tokens,
        "latency_ms": round(elapsed * 1000),
        "model": response.model,
        "stop_reason": response.stop_reason
    }

# ── Part 2: Bedrock boto3 Call ─────────────────────────────────────────────────
import boto3

def call_bedrock(prompt: str) -> dict:
    """Call Claude via Amazon Bedrock (boto3)."""
    # Requires AWS credentials configured:
    # aws configure OR AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY env vars
    try:
        bedrock = boto3.client(
            service_name="bedrock-runtime",
            region_name="us-east-1"
        )

        request_body = {
            "anthropic_version": "bedrock-2023-05-31",
            "max_tokens": 300,
            "system": "You are a helpful assistant. Be concise.",
            "messages": [{"role": "user", "content": prompt}]
        }

        start = time.time()
        response = bedrock.invoke_model(
            modelId="anthropic.claude-opus-4-5-20251101-v1:0",
            body=json.dumps(request_body),
            contentType="application/json",
            accept="application/json"
        )
        elapsed = time.time() - start

        body = json.loads(response["body"].read())
        return {
            "source": "Amazon Bedrock",
            "text": body["content"][0]["text"],
            "input_tokens": body["usage"]["input_tokens"],
            "output_tokens": body["usage"]["output_tokens"],
            "latency_ms": round(elapsed * 1000),
            "model": body.get("model", "bedrock-model"),
            "stop_reason": body.get("stop_reason")
        }

    except Exception as e:
        return {
            "source": "Amazon Bedrock",
            "text": f"[Error - AWS credentials needed: {str(e)[:100]}]",
            "input_tokens": 0, "output_tokens": 0, "latency_ms": 0,
            "model": "N/A", "stop_reason": "error"
        }

# ── Run Comparison ─────────────────────────────────────────────────────────────
def compare_providers(prompt: str):
    print(f"\nPrompt: {prompt}")
    print("="*60)

    sdk_result = call_anthropic_sdk(prompt)
    bedrock_result = call_bedrock(prompt)

    for result in [sdk_result, bedrock_result]:
        print(f"\n[{result['source']}]")
        print(f"  Model:         {result['model']}")
        print(f"  Input tokens:  {result['input_tokens']}")
        print(f"  Output tokens: {result['output_tokens']}")
        print(f"  Latency:       {result['latency_ms']}ms")
        print(f"  Stop reason:   {result['stop_reason']}")
        print(f"  Response:      {result['text'][:200]}")

compare_providers("What are the three most important considerations when designing a RAG pipeline?")
compare_providers("Write a Python one-liner that reverses a list.")

Bedrock with Tool Use (Function Calling)

import boto3, json

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")

# Tool use works identically to the Anthropic SDK — same JSON structure
request_body = {
    "anthropic_version": "bedrock-2023-05-31",
    "max_tokens": 500,
    "tools": [
        {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "input_schema": {
                "type": "object",
                "properties": {
                    "location": {"type": "string", "description": "City name"},
                    "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
                },
                "required": ["location"]
            }
        }
    ],
    "messages": [{"role": "user", "content": "What's the weather in Seattle?"}]
}

try:
    response = bedrock.invoke_model(
        modelId="anthropic.claude-opus-4-5-20251101-v1:0",
        body=json.dumps(request_body)
    )
    body = json.loads(response["body"].read())
    print(f"Stop reason: {body['stop_reason']}")
    for block in body.get("content", []):
        if block["type"] == "tool_use":
            print(f"Tool call: {block['name']}")
            print(f"Input: {json.dumps(block['input'], indent=2)}")
except Exception as e:
    print(f"[Needs AWS credentials]: {e}")
API parity: Claude's tool use, vision, streaming, and system prompts work identically on Bedrock — only the client initialization and model ID format differ. Migration from Anthropic SDK to Bedrock (or back) is a small refactor, not a rewrite.
