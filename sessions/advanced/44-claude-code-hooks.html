Claude Code Hooks — Define & Implement

Intercept Claude Code's execution with hooks: automatically log actions, enforce safety policies, and validate code quality before commands run.

45 min Advanced Code Lab 5 Quiz Questions

What Are Hooks?

Claude Code hooks are shell commands that run automatically at specific points in Claude Code's execution lifecycle. They let you extend Claude Code's behavior without modifying its core — you can intercept actions, validate outputs, log activity, or block dangerous operations.

Hooks are defined in settings.json (project-level at .claude/settings.json or global at ~/.claude/settings.json). Claude Code executes them as shell subprocesses.

Key mental model: Hooks are like git hooks but for Claude Code. pre-commit runs before a git commit; PreToolUse runs before Claude Code executes a tool. You can inspect inputs, modify behavior, or block the action entirely.

The Hook Lifecycle

Claude Code provides four hook points in the execution lifecycle:

PreToolUse
Before any tool runs
Tool Executes
PostToolUse
After tool completes
Notification
User-visible messages
Stop
When Claude finishes

Defining Hooks in settings.json

# .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",          // Which tool to intercept ("*" for all)
        "hooks": [
          {
            "type": "command",
            "command": "python3 /path/to/safety_hook.py"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "python3 /path/to/logging_hook.py"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 /path/to/completion_hook.py"
          }
        ]
      }
    ]
  }
}

How Hooks Receive Data

Claude Code passes context to hooks via stdin as a JSON payload. Your hook script reads this JSON to understand what Claude Code is about to do (or just did).

import json
import sys

# Hook receives context via stdin
input_data = json.loads(sys.stdin.read())

# For PreToolUse, the payload looks like:
# {
#   "session_id": "abc123",
#   "tool_name": "Bash",
#   "tool_input": {
#     "command": "rm -rf /tmp/test",
#     "description": "Clean up temp files"
#   }
# }

# For PostToolUse, it additionally includes:
# {
#   "tool_output": "...",
#   "tool_error": null
# }

Hook Exit Codes

Your hook's exit code tells Claude Code what to do:

Exit CodeMeaningClaude Code Behavior
0Success / AllowContinue normally
1Non-blocking warningLog the warning, continue
2Blocking errorStop the action, show error to user

Implementing a Logging Hook

#!/usr/bin/env python3
# /project/.claude/hooks/logging_hook.py
import json
import sys
import datetime
import os

input_data = json.loads(sys.stdin.read())

log_entry = {
    "timestamp": datetime.datetime.now().isoformat(),
    "session_id": input_data.get("session_id", "unknown"),
    "tool": input_data.get("tool_name"),
    "input": input_data.get("tool_input"),
}

log_file = os.path.expanduser("~/.claude/activity.log")
with open(log_file, "a") as f:
    f.write(json.dumps(log_entry) + "\n")

# Always exit 0 for logging hooks — don't block anything
sys.exit(0)

Implementing a Safety Hook

#!/usr/bin/env python3
# /project/.claude/hooks/safety_hook.py
"""Block dangerous shell commands before they run."""
import json
import sys
import re

DANGEROUS_PATTERNS = [
    (r'\brm\s+-rf\s+/', "Recursive delete from root is not allowed"),
    (r'\bchmod\s+777\b', "Setting 777 permissions is a security risk"),
    (r'>\s*/etc/', "Writing to /etc/ is not allowed"),
    (r'\bcurl\s+.*\|\s*(bash|sh)\b', "Pipe to shell from curl is not allowed"),
    (r'DROP\s+TABLE\b', "Dropping tables requires manual approval"),
]

input_data = json.loads(sys.stdin.read())
tool_name = input_data.get("tool_name", "")
tool_input = input_data.get("tool_input", {})

if tool_name == "Bash":
    command = tool_input.get("command", "")

    for pattern, message in DANGEROUS_PATTERNS:
        if re.search(pattern, command, re.IGNORECASE):
            # Print to stderr — this shows in Claude Code's UI
            print(f"SAFETY HOOK BLOCKED: {message}", file=sys.stderr)
            print(f"Command: {command[:100]}", file=sys.stderr)
            sys.exit(2)  # Exit 2 = blocking error

# If no dangerous patterns found, allow it
sys.exit(0)

Gotchas

  • Hooks run synchronously: Slow hooks (network calls, heavy processing) block Claude Code. Keep hooks fast (<500ms).
  • No stdin from user: Hooks can't prompt the user for input — they must be fully automated.
  • Errors in hooks: If your hook crashes (exception), Claude Code treats it as an exit code 1 (warning, non-blocking). Test your hooks thoroughly.
  • Hook ordering: Multiple hooks for the same event run in the order defined in settings.json.
  • Environment variables: Hooks inherit Claude Code's environment. You can use env vars for configuration.

Lab: Pre-Commit Hook That Validates Code Quality

Implement a PostToolUse hook that runs after Claude writes Python files, checking for common quality issues and logging a warning if found.

#!/usr/bin/env python3
# .claude/hooks/code_quality_hook.py
"""
PostToolUse hook: After Claude writes a .py file,
check basic code quality and log issues.
"""
import json
import sys
import ast
import re
import os
from pathlib import Path

def check_python_quality(file_path: str, content: str) -> list[dict]:
    """Check Python file for common quality issues."""
    issues = []

    # 1. Check syntax
    try:
        tree = ast.parse(content)
    except SyntaxError as e:
        issues.append({
            "severity": "ERROR",
            "check": "syntax",
            "message": f"Syntax error: {e.msg} at line {e.lineno}"
        })
        return issues  # Can't do further checks if syntax is broken

    # 2. Check for hardcoded secrets (simple patterns)
    secret_patterns = [
        (r'password\s*=\s*["\'][^"\']{3,}["\']', "Hardcoded password"),
        (r'api_key\s*=\s*["\'][^"\']{10,}["\']', "Hardcoded API key"),
        (r'secret\s*=\s*["\'][^"\']{5,}["\']', "Hardcoded secret"),
    ]
    for pattern, label in secret_patterns:
        matches = re.finditer(pattern, content, re.IGNORECASE)
        for match in matches:
            line_num = content[:match.start()].count('\n') + 1
            issues.append({
                "severity": "HIGH",
                "check": "secrets",
                "message": f"{label} detected at line {line_num}"
            })

    # 3. Check function documentation (public functions without docstrings)
    for node in ast.walk(tree):
        if isinstance(node, ast.FunctionDef):
            if not node.name.startswith('_'):  # Public function
                if not (node.body and isinstance(node.body[0], ast.Expr)
                        and isinstance(node.body[0].value, ast.Constant)):
                    issues.append({
                        "severity": "LOW",
                        "check": "documentation",
                        "message": f"Public function '{node.name}' at line {node.lineno} has no docstring"
                    })

    # 4. Check for overly long lines
    for i, line in enumerate(content.split('\n'), 1):
        if len(line) > 120:
            issues.append({
                "severity": "LOW",
                "check": "style",
                "message": f"Line {i} exceeds 120 characters ({len(line)} chars)"
            })

    return issues

def main():
    # Read hook input from Claude Code
    raw = sys.stdin.read()
    if not raw.strip():
        sys.exit(0)

    try:
        data = json.loads(raw)
    except json.JSONDecodeError:
        sys.exit(0)

    tool_name = data.get("tool_name", "")
    tool_input = data.get("tool_input", {})

    # Only check Write operations on Python files
    if tool_name != "Write":
        sys.exit(0)

    file_path = tool_input.get("path", "")
    if not file_path.endswith(".py"):
        sys.exit(0)

    content = tool_input.get("content", "")
    if not content:
        sys.exit(0)

    # Run quality checks
    issues = check_python_quality(file_path, content)

    if not issues:
        print(f"Quality check passed: {file_path}", file=sys.stderr)
        sys.exit(0)

    # Report issues
    high_issues = [i for i in issues if i["severity"] in ("ERROR", "HIGH")]
    low_issues = [i for i in issues if i["severity"] == "LOW"]

    print(f"\nCode Quality Report for {file_path}:", file=sys.stderr)
    for issue in issues:
        print(f"  [{issue['severity']}] {issue['message']}", file=sys.stderr)

    # Log to file for record-keeping
    log_path = Path(".claude/quality_log.jsonl")
    log_path.parent.mkdir(exist_ok=True)
    with open(log_path, "a") as f:
        import datetime
        f.write(json.dumps({
            "timestamp": datetime.datetime.now().isoformat(),
            "file": file_path,
            "issues": issues
        }) + "\n")

    if high_issues:
        print(f"\n⚠ {len(high_issues)} HIGH/ERROR issues found — please review!", file=sys.stderr)
        sys.exit(2)  # Block if there are serious issues (hardcoded secrets, syntax errors)
    else:
        print(f"\n{len(low_issues)} low-priority style issues noted.", file=sys.stderr)
        sys.exit(1)  # Warning only for low issues

if __name__ == "__main__":
    main()

Register the Hook in settings.json

Test the Hook Locally

import json
import subprocess

# Simulate what Claude Code sends to the hook
test_payload = {
    "tool_name": "Write",
    "tool_input": {
        "path": "test_module.py",
        "content": """
import os

password = "super_secret_123"  # This should trigger HIGH

def process_data(data):  # No docstring — should trigger LOW
    result = []
    for item in data:
        result.append(item * 2)
    return result
"""
    }
}

result = subprocess.run(
    ["python3", ".claude/hooks/code_quality_hook.py"],
    input=json.dumps(test_payload),
    capture_output=True,
    text=True
)

print(f"Exit code: {result.returncode}")
print(f"Stderr (shown in Claude Code UI):\n{result.stderr}")
Hook in action: This hook runs automatically every time Claude Code writes a .py file. It catches hardcoded secrets (exit 2 = blocks), notes style issues (exit 1 = warning), and logs everything to .claude/quality_log.jsonl for audit purposes.
