Introduction to Subagents

Understand what subagents are in Claude Code, how they differ from regular Claude, and when to use them for parallel tasks and specialized roles.

40 min Advanced Code Lab 5 Quiz Questions

What Are Subagents in Claude Code?

Claude Code has a built-in concept called subagents — separate Claude instances that a parent (orchestrator) agent can spawn to handle specific subtasks. Think of them like worker processes: the main agent delegates work to specialized workers, each with their own context, tools, and instructions.

When you use Claude Code and ask it to "work on multiple parts of this codebase simultaneously", it may spawn subagents. You can also explicitly create subagents using the Task tool or via claude --spawn in Claude Code SDK contexts.

Key mental model: Subagents are to Claude Code what threads are to programs. The orchestrator spawns them, gives them a task and context, and waits for results. Each subagent has its own clean context window — they don't share memory with each other.

Subagents vs Regular Claude Code

Regular Claude Code

  • Single conversation context
  • Sequential task execution
  • One set of tools and permissions
  • Context grows with every action
  • Simple, predictable

Subagents

  • Each subagent has its own fresh context
  • Parallel execution of independent tasks
  • Each can have different tools/permissions
  • Orchestrator only sees subagent outputs
  • More complex but far more powerful

How Subagents Are Spawned

In Claude Code, subagents are spawned via the built-in Task tool. The orchestrator calls Task with a description and prompt, and Claude Code creates a new agent instance to complete that task.

# This is how Claude Code internally handles subagent spawning.
# In Claude Code SDK, you can trigger this via the Task tool:

# Orchestrator calls:
# Task(description="Analyze the authentication module",
#      prompt="Read /src/auth/*.py and identify security issues")

# Claude Code spawns a new agent with:
# - Fresh context window
# - The same tools as the parent (or a subset)
# - The specific prompt and files the orchestrator provided
# - Returns a text summary to the orchestrator when done

Use Cases for Subagents

1. Parallel Independent Tasks

When tasks don't depend on each other, spawn them in parallel for faster completion:

# Orchestrator prompt (what you'd write in Claude Code):
"""
I need to review this codebase. Please:
1. Spawn a subagent to analyze the /src/auth/ directory for security issues
2. Spawn a subagent to check /src/api/ for performance bottlenecks
3. Spawn a subagent to review /tests/ for test coverage gaps
4. Once all three complete, synthesize their findings into a report.
"""

# Claude Code will internally use the Task tool 3 times in parallel,
# wait for all results, then write the synthesis.

2. Specialized Roles

Give each subagent a specific persona and focus area:

# Orchestrator instruction:
"""
Review this PR. Spawn three specialized reviewers:
- Security reviewer: focus only on security vulnerabilities
- Performance reviewer: focus only on algorithmic complexity and N+1 queries
- Style reviewer: focus only on code style and naming conventions
Combine their reviews into a final summary.
"""

3. Map-Reduce Pattern

Process a large dataset by splitting it across subagents (map), then aggregate (reduce):

# For a 100-file codebase:
# Map: spawn 10 subagents, each processes 10 files
# Reduce: orchestrator combines all findings

# This is exactly how Claude Code handles large codebase analysis —
# it doesn't read all 100 files in one context window!

Subagent Communication

Subagents communicate with their parent through their final output. The parent sees only the return value — not the subagent's internal reasoning or intermediate tool calls. This is important: design subagents to produce structured, useful outputs.

# Poor subagent output:
"I looked at the files and found some stuff."

# Good subagent output (structured and actionable):
"""
Security Analysis of /src/auth/:
- CRITICAL: SQL injection risk in auth.py:47 (unsanitized user input)
- MEDIUM: JWT secret stored in source code at config.py:12
- LOW: Password comparison not using constant-time comparison
Total files reviewed: 4
Files with issues: 2
"""

Context and Memory Isolation

Each subagent starts with a clean context. This is both a feature and a constraint:

  • Feature: Subagents don't pollute each other's context. They stay focused.
  • Constraint: Subagents can't "remember" what other subagents did. The orchestrator must explicitly share relevant context when spawning each subagent.
# WRONG: Assuming subagent knows what another did
Task(prompt="Now fix the issues you found earlier")  # Subagent has no memory of "earlier"

# RIGHT: Explicitly provide context
Task(prompt=f"""Fix these specific issues:
{previous_subagent_findings}

In these files: /src/auth/auth.py, /src/config.py
""")

Lab: Create Your First Claude Code Subagent

Simulate a subagent orchestration pattern using the Anthropic SDK to understand how orchestrators delegate to and communicate with subagents.

import anthropic
import json
from concurrent.futures import ThreadPoolExecutor, as_completed

client = anthropic.Anthropic()

# Simulate the subagent mechanism using the Anthropic SDK
# In Claude Code, this is done via the Task tool built into the environment

def run_subagent(task_description: str, prompt: str, context: str = "") -> dict:
    """
    Simulate a subagent: a fresh Claude instance with a specific task.

    Args:
        task_description: Brief name for this subagent's role
        prompt: The specific task prompt
        context: Any context the orchestrator shares with this subagent

    Returns:
        dict with subagent results
    """
    full_prompt = f"{context}\n\n{prompt}" if context else prompt

    response = client.messages.create(
        model="claude-haiku-4-5",  # Subagents often use faster models
        max_tokens=500,
        system=f"You are a specialized assistant focused on: {task_description}. Be concise and structured in your output.",
        messages=[{"role": "user", "content": full_prompt}]
    )

    return {
        "subagent": task_description,
        "output": response.content[0].text,
        "tokens_used": response.usage.input_tokens + response.usage.output_tokens
    }

def orchestrate_code_review(code: str) -> str:
    """
    Orchestrator: spawns 3 specialized subagents to review code in parallel,
    then synthesizes their findings.
    """
    print("Orchestrator: Spawning 3 specialized review subagents in parallel...")

    # Define subagent tasks
    subagent_tasks = [
        (
            "Security Reviewer",
            f"Review this Python code for security vulnerabilities only. List issues as: [SEVERITY] description:\n\n{code}"
        ),
        (
            "Performance Reviewer",
            f"Review this Python code for performance issues only (complexity, N+1 queries, inefficient patterns). List issues:\n\n{code}"
        ),
        (
            "Style Reviewer",
            f"Review this Python code for style and readability issues only (naming, documentation, structure). List issues:\n\n{code}"
        )
    ]

    # Fan-out: spawn all subagents in parallel
    results = []
    with ThreadPoolExecutor(max_workers=3) as executor:
        futures = {
            executor.submit(run_subagent, desc, prompt): desc
            for desc, prompt in subagent_tasks
        }
        for future in as_completed(futures):
            result = future.result()
            results.append(result)
            print(f"  Subagent '{result['subagent']}' completed ({result['tokens_used']} tokens)")

    # Fan-in: orchestrator synthesizes all subagent outputs
    print("\nOrchestrator: All subagents done. Synthesizing results...")

    findings_text = "\n\n".join([
        f"=== {r['subagent']} ===\n{r['output']}"
        for r in results
    ])

    synthesis = client.messages.create(
        model="claude-opus-4-5",  # Orchestrator uses more capable model for synthesis
        max_tokens=600,
        system="You are a senior code review coordinator. Synthesize specialist reviews into an actionable final report.",
        messages=[{
            "role": "user",
            "content": f"""Three specialized code reviewers have analyzed the code.
Synthesize their findings into a prioritized action plan.

{findings_text}

Write a final report with:
1. Top 3 most critical issues to fix immediately
2. Medium priority improvements
3. Quick wins / style fixes"""
        }]
    )

    return synthesis.content[0].text

# Test with sample code
SAMPLE_CODE = """
import sqlite3
import hashlib

def get_user(username, password):
    conn = sqlite3.connect('users.db')
    cursor = conn.cursor()
    # Get user from database
    query = f"SELECT * FROM users WHERE username = '{username}'"
    cursor.execute(query)
    user = cursor.fetchone()
    if user and user[2] == password:  # Compare plaintext passwords
        return user
    return None

def process_items(user_id):
    conn = sqlite3.connect('items.db')
    items = conn.execute(f"SELECT * FROM items WHERE owner={user_id}").fetchall()
    results = []
    for item in items:
        # Load details for each item
        detail = conn.execute(f"SELECT * FROM details WHERE item_id={item[0]}").fetchone()
        results.append((item, detail))
    return results
"""

print("Starting multi-subagent code review...\n")
report = orchestrate_code_review(SAMPLE_CODE)
print("\n" + "="*60)
print("FINAL CODE REVIEW REPORT")
print("="*60)
print(report)
The subagent pattern in action: Each specialist subagent had a fresh context focused only on its domain (security/performance/style). The orchestrator never showed each subagent the others' findings — isolation is key. The synthesis step is where the orchestrator adds value by combining perspectives.
