Agent Skills — Create, Configure & Share

Build reusable Claude Code skills that encapsulate workflows, share them with your team, and understand how skills differ from hooks and MCP tools.

45 min Advanced Code Lab 5 Quiz Questions

What Are Agent Skills?

Skills are reusable, packaged Claude Code workflows that can be invoked with a slash command. They're the Claude Code equivalent of shell aliases or npm scripts — instead of typing a long instruction every time, you type /skill-name and Claude Code runs the pre-defined workflow.

Skills live in .claude/skills/ (project) or ~/.claude/skills/ (global). A skill is a Markdown file that contains the workflow prompt Claude Code should execute when invoked.

Quick example: Instead of typing "Review the last commit for security issues, check all changed files, and provide a structured report" every time, you create a skill and type /security-review. The skill contains the full instruction set.

Skills vs Hooks vs MCP

Skills

  • Invoked manually with /slash-command
  • Reusable workflow instructions
  • Stored as Markdown files
  • Can use all of Claude Code's tools
  • Shareable via Git repository

Hooks

  • Triggered automatically by events
  • Run on every matching tool use
  • Shell scripts (Python, bash, etc.)
  • Can intercept and block actions
  • Not invoked by user directly

MCP Tools

  • External capabilities Claude can call
  • Defined by MCP server protocol
  • Can be remote services (APIs, databases)
  • Available as tools in all sessions
  • More complex to implement

Creating a Single-File Skill

The simplest skill is a single Markdown file. The filename becomes the slash command (with / prefix).

# File: .claude/skills/security-review.md
# Invoked with: /security-review
---
description: Review the current branch's changes for security vulnerabilities
author: Your Team
version: 1.0.0
---

# Security Review

You are performing an automated security review of this branch's changes.

## Process

1. Get the list of changed files: `git diff --name-only main...HEAD`
2. For each changed file, read its content
3. Check for these security issues:
   - SQL injection (f-strings in queries, string concatenation in SQL)
   - Hardcoded secrets (passwords, API keys, tokens in source)
   - Insecure deserialization (pickle.loads, yaml.load without Loader)
   - Path traversal (user input used in file paths without sanitization)
   - Command injection (user input in os.system, subprocess, eval)
   - Insecure direct object references (user IDs used without authorization check)

## Output Format

For each issue found:
**[SEVERITY]** `file.py:line` — Description

Severity levels: CRITICAL, HIGH, MEDIUM, LOW

## Final Summary

End with:
```
Security Review Summary
-----------------------
Files reviewed: N
Issues found: N (CRITICAL: N, HIGH: N, MEDIUM: N, LOW: N)
PR Status: [PASS | REVIEW REQUIRED | BLOCKED]
```

Creating a Multi-File Skill

For complex workflows, create a directory with a main.md entry point and supporting files:

# .claude/skills/code-review/
# ├── main.md          ← Entry point (invoked with /code-review)
# ├── security.md      ← Included by main.md
# ├── performance.md   ← Included by main.md
# └── README.md        ← Documentation for skill users
# .claude/skills/code-review/main.md
---
description: Comprehensive code review covering security, performance, and style
includes: [security.md, performance.md]
---

# Comprehensive Code Review

Run the following review checklist on all changed files.

## Security Check
{{include: security.md}}

## Performance Check
{{include: performance.md}}

## Synthesis
After completing all checks, write a single unified report prioritizing the
most impactful issues. Group by severity.

Skill Configuration

The YAML frontmatter configures how the skill behaves:

---
description: Generate unit tests for all new functions    # Shown in /help
author: engineering-team
version: 2.1.0
model: claude-opus-4-5                # Override default model
max_turns: 15                         # Allow more iterations for complex tasks
allowed_tools: [Read, Write, Bash]    # Restrict to only needed tools
args:                                 # Declare arguments the skill accepts
  - name: coverage_target
    description: Target test coverage percentage
    default: "80"
  - name: test_framework
    description: Testing framework to use
    default: "pytest"
---

# Generate Tests

Generate unit tests for all new functions in this PR.
Target coverage: {{args.coverage_target}}%
Framework: {{args.test_framework}}

Sharing Skills with Your Team

The simplest way to share skills is via your Git repository:

# 1. Commit skills to your repo
git add .claude/skills/
git commit -m "Add team skills: security-review, generate-tests, release-notes"

# 2. Team members who clone the repo automatically get the skills
git clone https://github.com/org/project
cd project
claude  # /security-review now available!

# 3. For global skills (personal, not project-specific), use:
# ~/.claude/skills/my-personal-skill.md
# These aren't shared but available in all your projects

Troubleshooting Skills

  • Skill not appearing in /help: Check the file is in .claude/skills/ and has a .md extension. Restart Claude Code.
  • Skill running but ignoring instructions: The YAML frontmatter may be malformed. Check indentation and that frontmatter starts and ends with ---.
  • Args not being substituted: Use {{args.name}} syntax exactly. Declare all args in frontmatter.
  • Skill exits immediately: If max_turns is too low for the task, the skill will stop early. Increase max_turns.

Lab: Create, Configure, and Share a Custom Skill

Build a complete "generate-changelog" skill that reads git log, analyzes commits, and writes a formatted CHANGELOG.md entry.

Step 1: Create the Skill File

# Create the directory
import os
os.makedirs(".claude/skills", exist_ok=True)

# Write the skill
skill_content = '''---
description: Generate a formatted CHANGELOG.md entry from recent git commits
author: your-name
version: 1.0.0
max_turns: 8
allowed_tools: [Bash, Read, Write]
args:
  - name: since
    description: "Git ref to generate log from (e.g., v1.2.0 or HEAD~10)"
    default: "HEAD~10"
  - name: version
    description: "Version number for this changelog entry"
    default: "Unreleased"
---

# Generate Changelog

Generate a formatted CHANGELOG.md entry following the Keep a Changelog format.

## Steps

1. Get the commit log since {{args.since}}:
   ```bash
   git log {{args.since}}..HEAD --oneline --no-merges
   ```

2. Read the current CHANGELOG.md if it exists (to understand the format and prepend the new entry)

3. Categorize commits into:
   - **Added** — new features (feat:, add:, new:)
   - **Changed** — changes to existing functionality (change:, update:, refactor:)
   - **Fixed** — bug fixes (fix:, bug:)
   - **Security** — security fixes (security:, cve:)
   - **Removed** — removed features (remove:, delete:)
   - **Deprecated** — soon-to-be removed (deprecate:)

4. Write a new CHANGELOG entry at the top of CHANGELOG.md in this format:

```markdown
## [{{args.version}}] - YYYY-MM-DD

### Added
- Description of new feature

### Fixed
- Description of bug fix

### Changed
- Description of change
```

5. Confirm the file was written and show a preview of the first 30 lines.
'''

with open(".claude/skills/generate-changelog.md", "w") as f:
    f.write(skill_content)

print("Skill created at .claude/skills/generate-changelog.md")
print("Use with: /generate-changelog")
print("Or with args: /generate-changelog --since v1.0.0 --version 1.1.0")

Step 2: Simulate Skill Execution with the Anthropic API

import anthropic
import subprocess
import datetime

client = anthropic.Anthropic()

def simulate_generate_changelog(since="HEAD~5", version="Unreleased"):
    """Simulate what the /generate-changelog skill would do."""

    # Get git log (the Bash tool would do this in real Claude Code)
    try:
        git_log = subprocess.check_output(
            ["git", "log", f"{since}..HEAD", "--oneline", "--no-merges"],
            text=True, stderr=subprocess.DEVNULL
        ).strip()
    except subprocess.CalledProcessError:
        git_log = """a1b2c3d feat: Add RAG pipeline with FAISS support
b2c3d4e fix: Fix SQL injection vulnerability in auth module
c3d4e5f refactor: Simplify BM25 search implementation
d4e5f6g feat: Add contextual retrieval with prompt caching
e5f6g7h security: Update cryptography library to fix CVE-2024-1234
f6g7h8i docs: Update README with SDK examples"""

    if not git_log:
        git_log = "No commits found in range"

    today = datetime.date.today().isoformat()

    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=800,
        system="""You are a release manager writing a CHANGELOG.md entry.
Follow the Keep a Changelog format exactly.
Categorize commits into: Added, Changed, Fixed, Security, Removed, Deprecated.
Write clear, user-facing descriptions (not just commit messages).""",
        messages=[{
            "role": "user",
            "content": f"""Generate a CHANGELOG.md entry for version {version}.

Recent commits:
{git_log}

Today's date: {today}

Write the complete CHANGELOG entry in markdown format."""
        }]
    )

    changelog_entry = response.content[0].text

    # Write to file
    try:
        try:
            existing = open("CHANGELOG.md").read()
        except FileNotFoundError:
            existing = "# Changelog\n\nAll notable changes to this project will be documented in this file.\n\n"

        with open("CHANGELOG.md", "w") as f:
            # Insert new entry after the first two lines (title + description)
            lines = existing.split('\n')
            header = '\n'.join(lines[:3])
            rest = '\n'.join(lines[3:])
            f.write(header + '\n\n' + changelog_entry + '\n' + rest)

        print("CHANGELOG.md updated!")
    except Exception as e:
        print(f"Note: Could not write file ({e}), showing output:")

    print("\n" + "="*50)
    print("GENERATED CHANGELOG ENTRY:")
    print("="*50)
    print(changelog_entry)

simulate_generate_changelog(since="HEAD~5", version="1.1.0")

Step 3: Verify Skill Registration

import os
from pathlib import Path

# Check skill files
skills_dir = Path(".claude/skills")
if skills_dir.exists():
    skills = list(skills_dir.glob("*.md")) + list(skills_dir.glob("*/main.md"))
    print(f"Registered skills ({len(skills)}):")
    for skill_file in skills:
        # Read frontmatter description
        content = skill_file.read_text()
        desc_line = [l for l in content.split('\n') if l.startswith('description:')]
        desc = desc_line[0].replace('description:', '').strip() if desc_line else "No description"

        skill_name = skill_file.stem if skill_file.name != "main.md" else skill_file.parent.name
        print(f"  /{skill_name} — {desc}")
else:
    print("No .claude/skills directory found")
    print("Run: mkdir -p .claude/skills")
Skill created and tested! Your /generate-changelog skill is ready to use. Commit .claude/skills/ to Git and everyone on the team can use it immediately. Skills are the highest-leverage way to standardize Claude Code workflows across your organization.
